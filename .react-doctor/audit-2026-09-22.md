## Security and data integrity fixes

- Class details previously returned nested users including password hashes. Shared
  profile projections now exclude credentials from those queries and other user
  relations; a route regression verifies teacher and student responses.
- Existing session cookies previously survived account deletion, demotion, and
  password changes. Session validation now checks the live account, role, and a
  SHA-256 fingerprint of its salted password hash. The pressure-test cookie minter
  stamps the same claim. Profile and consent refresh behavior remains tested.
- Reset-token redemption now checks expiry and ownership in its atomic claim,
  including expiry while hashing the replacement password. New passwords reject
  inputs beyond bcrypt's 72-byte UTF-8 boundary rather than silently truncating.
- Invitation creation and its server-rendered management page now reject a missing
  teacher profile before constructing an ownership query. Previously `undefined`
  could omit the Prisma filter and expose another teacher's class invitations.
- Questions, quizzes, topics, invitations, and teacher email-limit edits validate
  bounded JSON bodies. Invalid primitives, field types, choice modes, oversized
  bodies, and invalid numeric limits return client errors before writes.
- Editing a question updates retained options in place, preserving option IDs,
  image metadata, and existing student-answer references. The entire update is
  transactional. Effective stored answer modes are validated, and edits use the
  same authoring guardrail as new questions.

**Deployment behavior:** existing sessions lack the new credential fingerprint and
will require one new sign-in. Password changes also revoke the changing user's old
session. No schema migration is required. Live session validation adds a database
read; production load impact has not been measured in this audit. The old README
contained a literal demo credential; it has been removed. If that credential is
still active in any deployment, it needs rotation there; deleting the text does
not revoke it or erase its Git history.

## Reliability, accessibility, and readability

- Assistant attachment ownership is explicit: retained previews survive rerenders;
  removed, cleared, sent, abandoned, and unmounted previews are released. Concurrent
  preparation reserves slots, and one unreadable file does not discard its peers.
- Assistant conversation selection and streaming have independent cancellation and
  ownership checks. Old responses cannot replace a newly selected transcript or
  clear a successor's busy state. IME composition does not submit on Enter.
- QuizEditor and AssistantWidget are decomposed into focused UI components and
  state/lifecycle hooks. Failed saves preserve the form; failed deletes preserve
  the question; duplicate saves are blocked until the current request completes.
- Transcript rows use real buttons. Radix Dialog supplies modal focus trapping and
  Escape handling, with explicit return focus to the selected row and stable turn
  keys. Request identity prevents stale list responses overwriting newer filters.
- Notification refreshes and settings/admin/teacher loads ignore cancelled results.
  Material/consent/quiz polling avoids overlapping requests. Network errors during
  material tagging are surfaced; PDF resume lookup cannot revive an old effect.
- A simulation session created after the viewer closes receives a final telemetry
  flush with the actual dwell time. A rejected beacon falls back to keepalive fetch.
- Demo seeding no longer prints a newly generated password for an unchanged existing
  account. README setup links/version/credentials are corrected. CI now checks
  types, formatting, and the worker bundle as well as tests and the web build.
  Next.js generated `AGENTS.md` and `CLAUDE.md` on startup; these framework guidance
  files are included as recorded collateral.

## Dependency decisions

Targeted lockfile updates cover OpenTelemetry 2.11.0 and js-yaml 4.3.2. Prisma-scoped
overrides select mysql2 3.24.4 and deepmerge-ts 8.0.2. Prisma remains at 7.10.0.
The deepmerge major change was checked against Prisma's usage: its config loader
uses `deepmerge` on plain configuration objects, not Maps, `deepmergeInto`, or the
renamed type utilities. A plain `npm ci`, Prisma generation/schema push, tests,
and both builds validate this project's boundary. Revisit these temporary overrides
when Prisma's transitive requirements include patched versions.

## Runtime evidence and limits

Headless Chrome used an isolated temporary SQLite database and locally seeded
accounts. Desktop 1280×900 and mobile 390×844 screenshots were inspected. Verified:
actual login, transcript keyboard opening, trapped Tab, Escape, restored opener
focus, mobile dialog bounds, and an actual quiz option edit/save. No browser
`pageerror` events occurred. The built-in preview automation was unavailable, so
local Playwright drove the installed Chrome without adding a project dependency.

Regression tests additionally cover late/stale assistant responses, attachment
lifetime/capacity, notification ordering, delayed telemetry and beacon fallback,
failed/double quiz saves, authorization, invalid bodies, reference preservation,
reset-token races, session revocation, and UTF-8 password boundaries.

Not run: production traffic/load traces, real cloud storage/email/paid AI calls,
backup/restore against a deployed system, all browser engines, assistive-technology
screen-reader testing, RTL, dark-theme, and reduced-motion visual comparisons.
External integrations are exercised by existing mocked/unit/route tests only.
